01 Обзор темы

Зачем дженерики, если есть interface{}

До Go 1.18 «контейнер чего угодно» держал interface{} и возвращал его же — а вызывающий руками приводил тип обратно. Компилятор при этом молчал: ошибку ловил только рантайм. Дженерики переносят проверку на этап компиляции и сохраняют конкретный тип на входе и выходе.

🕹️ Старый способ до 1.18

Хранили interface{}, на выходе — приведение типа. Ошибся типом — паника в рантайме, компилятор не помог.

s := []interface{}{}
s = append(s, 42)
v := s[0].(int)     // приведение
x := s[0].(string)  // ПАНИКА

✅ Дженерики Go 1.18+

Параметр типа [T any]: Stack[int] держит только int, Pop сразу отдаёт int. Ошибку типа поймает компилятор.

var s Stack[int]
s.Push(42)
v, ok := s.Pop()    // v уже int
s.Push("текст")     // ошибка КОМПИЛЯЦИИ

Ровно на дженериках держатся современные пакеты стандартной библиотеки — slices и maps. Этот проект собирает такой же маленький типобезопасный тулкит своими руками.

02 Карта проекта

Тулкит, раскрашенный по силе ограничения

Каждая часть тулкита требует от типа ровно столько, сколько ей нужно. Цвет показывает ограничение: any (любой тип), comparable (можно ==), Number / Ordered (арифметика и порядок). Чем строже — тем меньше типов подойдёт, но тем больше можно внутри.

any — любой тип comparable — == Number/Ordered — + - * · < >
03 Параметр типа [T]

Из шаблона — конкретный тип

Stack[T any] — это шаблон, а не готовый тип. Пока не подставишь конкретный T, стека нет. Подстановка называется инстанциацией: Stack[int] и Stack[string] — два разных, полностью проверенных типа. Часто T писать не нужно — компилятор выведет его из аргументов.

🧩

Методы не вводят своих параметров типа. Их объявляет только сам тип (Stack[T]), а методы лишь используют T. Нужен новый параметр (как U в Map) — это обычная функция, а не метод: func (s *Stack[T]) MapTo[U any](…) не скомпилируется.

04 Stack и Queue

LIFO против FIFO и приём (T, bool)

Обе коллекции — это срез []T внутри и параметр [T any]. Разница лишь в том, с какого конца снимаем: стек — сверху (последний вошёл — первый вышел), очередь — с начала (первый вошёл — первый вышел). Из пустой коллекции возвращаем не панику, а (нулевое значение, false).

05 Set: comparable

Почему множеству нужен именно comparable

Set[T] — это map[T]struct{}: наличие ключа означает «элемент есть», а значение struct{} занимает 0 байт. Но ключ карты в Go обязан быть сравним через == — поэтому Set[T any] не скомпилируется, нужен Set[T comparable].

🚫

Set[T any] не скомпилируется. Сообщение компилятора: T does not satisfy comparable. Ключу карты нужен ==, а any его не гарантирует (например, срез сравнивать через == нельзя). Ставь T comparable.

06 Map / Filter / Reduce

Конвейер над срезами: []T → []U

Три универсальные функции над []T. У Map — два параметра типа: вход T и выход U, поэтому он умеет менять тип ([]int → []string). Filter тип сохраняет (один T), а Reduce сворачивает весь срез в одно значение U.

07 Лестница ограничений

Чем строже — тем больше можно внутри

Ограничение — это контракт о том, что разрешено делать с T. Поднимаясь по лестнице, мы получаем больше операций (==, потом + - *, потом < >), но круг подходящих типов сужается. Правило простое: бери минимально необходимое.

🔢

Тильда ~ в union. Number перечисляет ~int | ~float64 | …. ~int значит «int и любой тип с базой int» — поэтому объявленный type Age int тоже проходит в Sum. Без тильды (int) подошёл бы только сам int, но не Age.

08 Грабли дженериков

Что не компилируется и что паникует

Часть ошибок дженериков ловит компилятор (это хорошо — до рантайма не дойдёт), но пара ловушек остаётся на рантайм. Ниже — самые частые в этом проекте.

① Set[T any] компиляция

Ключу карты нужен ==. Set[T any] → T does not satisfy comparable. Ставь T comparable.

② a + b под [T any] компиляция

Компилятор не знает, есть ли у T оператор +. Нужен union-constraint (Number), либо cmp.Ordered для < >.

③ Add в nil-множество рантайм

Нулевое значение Set[T] — nil-карта. Has/Remove на ней ок, а Add паникует. Создавай через NewSet/make.

④ Метод со своим [U] компиляция

Параметр типа вводит только сам тип. Нужен новый U — это обычная функция (Map), а не метод Stack.MapTo[U].

⑤ Pop/Dequeue пустого контракт

Возвращай (нулевое значение, false), а не панику. Всегда отдавай второй bool и проверяй его у вызывающего.

⑥ Дженерики ради дженериков стиль

Если хватает интерфейса (io.Writer, fmt.Stringer) — бери его, он проще. Дженерики — когда важно сохранить конкретный тип на входе и выходе.

🏁

Проверь себя инструментами. Большинство ошибок дженериков — на этапе компиляции, поэтому первый рубеж это go build. Дальше:

go vet ./...  ·  go test -race ./...
