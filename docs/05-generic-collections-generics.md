# Проект 5: generic-collections — тема: дженерики (Go 1.18+)

> *Сделав это, ты поймёшь, как писать типобезопасный код, который работает с любым типом — без `interface{}` и приведений типа.*

## 🎯 Какую тему осваиваем

До Go 1.18, чтобы написать «стек чего угодно», приходилось хранить `interface{}` и потом руками приводить значения обратно (`v.(int)`) — легко ошибиться и словить панику. **Дженерики** решают это: ты пишешь код один раз с «параметром типа», а компилятор подставляет конкретный тип и проверяет всё заранее. Тема важная, потому что на дженериках держатся современные коллекции и утилиты (`slices`, `maps` в стандартной библиотеке). Научишься писать `Stack[int]`, `Set[string]` и функции `Map`/`Filter`, которые не теряют тип.

## 🧩 Что моделируем

Небольшой набор **типобезопасных коллекций** — свой мини-«тулкит». Стек (кладём наверх, снимаем сверху), очередь (кладём в конец, берём с начала) и множество (хранит уникальные значения, умеет отвечать «есть такое или нет»). Плюс пара универсальных функций над срезами: превратить один срез в другой (`Map`), отфильтровать (`Filter`), свернуть в одно значение (`Reduce`). Всё это должно одинаково хорошо работать и с числами, и со строками, и с твоими структурами.

## ✅ Что программа должна уметь

- `Stack[T]`: `Push`, `Pop` (снять сверху), пустой ли.
- `Queue[T]`: `Enqueue`, `Dequeue` (взять с начала).
- `Set[T comparable]`: добавить, проверить наличие, удалить, размер.
- `Map`, `Filter`, `Reduce` — универсальные функции над `[]T`.
- Никаких `interface{}` и приведений типа: тип известен на этапе компиляции.

## 🧠 Ключевые концепции Go

**Параметр типа `[T any]`.** В квадратных скобках после имени объявляем «переменную-тип». `any` — это ограничение «любой тип» (псевдоним `interface{}`). Внутри `T` — обычный тип:

```go
type Stack[T any] struct {
    items []T
}
```

**Инстанциация — подставляем конкретный тип.** `Stack[int]` — это уже конкретный тип «стек интов». Часто тип можно не писать — компилятор выведет его из аргументов:

```go
s := Stack[int]{}          // явно
nums := Map([]int{1, 2}, double) // T и U выведутся сами
```

**Ограничения (constraints).** Ограничение говорит, «что разрешено делать с `T`». `any` — ничего особенного. `comparable` — тип можно сравнивать через `==` (нужно для ключей карты и множества):

```go
type Set[T comparable] map[T]struct{}
```

**Своё интерфейс-ограничение.** Ограничение — это интерфейс. Можно потребовать, чтобы у типа был нужный метод:

```go
type Stringer interface {
    String() string
}

func Join[T Stringer](in []T, sep string) string
```

**Числовое ограничение — для арифметики.** Просто так `a + b` над `T` не написать: не для всякого типа есть `+`. Нужен список разрешённых типов (union). Проще всего задать свой union через `~` (см. `Number` ниже). Есть и готовые ограничения в `golang.org/x/exp/constraints`, но выбирай по смыслу: `constraints.Integer` / `constraints.Float` — это числа, а `constraints.Ordered` **шире** — все упорядочиваемые типы, включая строки (у строк есть `+`, но нет `-` / `*`).

```go
type Number interface {
    ~int | ~int64 | ~float64
}

func Sum[T Number](in []T) T // теперь внутри можно a + b
```

(`~int` значит «`int` и любой тип с базой `int`», например `type Age int`.)

**Универсальные функции над срезами.** Два параметра типа: вход `T`, выход `U`:

```go
func Map[T, U any](in []T, f func(T) U) []U
func Filter[T any](in []T, keep func(T) bool) []T
```

**Методы не вводят своих параметров типа.** Параметры типа объявляет только сам тип (`Stack[T]`), а методы их лишь используют. Своё `[U]` в методе — ошибка компиляции:

```go
func (s *Stack[T]) Push(v T)          // ок: T взят у типа
// func (s *Stack[T]) MapTo[U any](...) // нельзя!
```

**Когда дженерики НЕ нужны.** Если функции хватает обычного интерфейса (`io.Writer`, `fmt.Stringer`) — бери интерфейс, он проще. Дженерики — когда важно **сохранить конкретный тип** на входе и выходе.

## 🗂 Подсказка по структуре

Раскидай по файлам по смыслу:

- `stack.go` — `Stack[T]` и его методы.
- `queue.go` — `Queue[T]`.
- `set.go` — `Set[T comparable]`.
- `slices.go` — функции `Map`, `Filter`, `Reduce`.
- `main.go` — маленький сценарий: положить, снять, отфильтровать, вывести.
- `*_test.go` — тесты.

Наброски (сигнатуры, не реализация):

```go
type Stack[T any] struct {
    items []T
}

func (s *Stack[T]) Push(v T)
func (s *Stack[T]) Pop() (T, bool) // (значение, есть ли оно)
func (s *Stack[T]) Len() int

type Queue[T any] struct {
    items []T
}

func (q *Queue[T]) Enqueue(v T)
func (q *Queue[T]) Dequeue() (T, bool)

type Set[T comparable] map[T]struct{}

// Карту надо создать ДО Add (иначе паника «assignment to entry in nil map»):
func NewSet[T comparable]() Set[T] { return make(Set[T]) }

func (s Set[T]) Add(v T)
func (s Set[T]) Has(v T) bool
func (s Set[T]) Remove(v T)

func Map[T, U any](in []T, f func(T) U) []U
func Filter[T any](in []T, keep func(T) bool) []T
func Reduce[T, U any](in []T, init U, f func(U, T) U) U
```

Идея `Pop`: если стек пуст — вернуть **нулевое значение** типа и `false`; иначе снять последний элемент и вернуть его с `true`. Нулевое значение удобно получить так:

```go
var zero T
return zero, false
```

## ⚠️ Грабли и на что смотреть

- **Для ключей нужен `comparable`.** `Set[T any]` не скомпилируется: `map` требует сравнимый ключ. Ставь `T comparable`.
- **Без числового ограничения нельзя `a + b`.** Под `[T any]` компилятор не знает, есть ли у типа `+`. Нужен union-constraint (`Number`, либо `constraints.Integer` / `constraints.Float`). `constraints.Ordered` тоже подойдёт, но помни: он включает и строки.
- **`Pop`/`Dequeue` из пустого — это (нулевое значение, false), а не паника.** Всегда возвращай второй `bool` и проверяй его у вызывающего.
- **Методы со своими `[U]` запрещены.** Нужен новый параметр типа — делай обычную функцию (`Map`), а не метод.
- **Не «генерь» всё подряд.** Если хватает интерфейса — читаемость важнее. Дженерики ради дженериков усложняют код.
- **Указатель у методов, меняющих состояние.** `Push`/`Pop` меняют `items`, поэтому ресивер `*Stack[T]`. У `Set` (это карта) ресивер-значение — карта и так ссылочная.
- **`Set` нужно создать до `Add`.** Нулевое значение `Set[T]` — это `nil`-карта: `Has`/`Remove` на ней безопасны, но `Add` **паникует** («assignment to entry in nil map»). Создавай через `make`/`NewSet`. В отличие от `Stack`/`Queue`, где нулевое значение сразу рабочее (там `append`).

## 🔬 Как запускать и проверять

```sh
go run .            # прогнать сценарий из main.go
go test ./...       # запустить тесты
go vet ./...        # ловит подозрительные места
```

Тесты удобно писать сразу под конкретный тип — так проверяется и логика, и то, что тип «донёсся»:

```go
var s Stack[int]
if _, ok := s.Pop(); ok {
    t.Fatal("пустой стек не должен ничего отдавать")
}
s.Push(42)
if v, ok := s.Pop(); !ok || v != 42 {
    t.Fatalf("ожидали 42, получили %v, ok=%v", v, ok)
}
```
